# Capture meetings continuously with bounded loss

Archived September 30, 2026 bootstrap report for maintainers. Its indexed filenames, dependency state, CLI examples and verification boundaries describe that snapshot. Source links point to the current tree, which can differ from the measured build. Read the [contributor instructions](../../contributing.md) and [embedded usage reference](../../../../cmd/ambient-recorder/SKILL.md) for current behavior.

The macOS Go CLI records **microphone plus playback into mono Ogg Opus**, using native Core Audio and statically linked Xiph libraries. A real 157.12-second recording decoded successfully with an injected 880 Hz playback tone; progress diagnostics reported zero dropped frames. On this Apple M4 Pro/macOS 26.6.2 machine, an earlier build used approximately **1.42% of one CPU core** during a measured 157.75-second run; the subsequent clock comparison is not benchmarked. A SIGKILL-interrupted file retained a decodable 52.294-second prefix, and restarting allocated the next suffix. The user approved the exact dependency set and Go 1.27.1. **A crash can still lose buffered audio and leave an incomplete tail**; these experiments do not establish uninterrupted operation. Background execution, physical-device changes, and long-duration measurements remain unverified; transcription, VAD, and calendar integration remain later work. The [verification record](verification.md) links retained execution evidence and its boundaries. ([Live decode](evidence/live-decode.log), [CPU measurement](evidence/live-time5.log), [crash decode](evidence/crash-decode.log))

## Native capture covers microphone and playback from macOS 14.2

The implemented [native bridge](../../../../internal/capture/native.m) creates an **unmuted private global process tap** and a private aggregate using the default microphone as its main device, with tap drift compensation enabled. It checks float PCM layouts, averages channels into mono, retains acquisition host/sample timestamps, and copies into a bounded native queue with overflow counters. Encoding and filesystem work execute outside the native callback. Apple supports process taps from macOS 14.2, and its aggregate guidance describes private devices and synchronization. ([Apple process taps](https://developer.apple.com/documentation/coreaudio/capturing-system-audio-with-core-audio-taps), [Apple aggregates](https://developer.apple.com/library/archive/documentation/MusicAudio/Conceptual/CoreAudioOverview/ARoadmaptoCommonTasks/ARoadmaptoCommonTasks.html), [IOProc timestamps](https://developer.apple.com/documentation/coreaudio/audiodeviceioproc))

The [native probe](evidence/native-probe.log) observed a 16 kHz Bluetooth microphone/aggregate while the tap stream advertised 48 kHz; both callback buffers contained 320 frames, corresponding to 20 ms at the aggregate rate. The implementation uses the aggregate clock and verifies callback buffer lengths, rather than rejecting the tap's original advertised rate. The real file decoded to **157.120 seconds, EOS present, and 7,542,720 samples at 48 kHz**, with detected 880 Hz playback amplitude 0.099859. This establishes successful playback capture through this tested topology, not correctness across every device, clock change, or acoustic microphone condition. ([Decode evidence](evidence/live-decode.log))

The third-party capture candidates do not currently meet the complete requirement with verified timing and loss diagnostics. Malgo bundles miniaudio and avoids an installed macOS capture library, but miniaudio's loopback API is WASAPI-only. PortAudio's Go binding requires separately available development headers and libraries. The closer macOS candidate, graphaelli/audiotap, embeds native code, yet inspected microphone code does not negotiate/resample native rates, ignores a restart result, and its bridge omits timestamps and overflow diagnostics. Autogenerated tmc/apple bindings remain an alternative to evaluate, but its systap example allocates, locks, and writes files in its callback. These findings favor direct native capture while delegating encoding and container handling to upstream libraries. ([malgo](https://github.com/gen2brain/malgo), [miniaudio manual](https://miniaud.io/docs/manual/index.html), [PortAudio Go binding](https://github.com/gordonklaus/portaudio), [audiotap microphone source](https://github.com/graphaelli/audiotap/blob/main/src/audiotap_mic.c), [audiotap bridge](https://github.com/graphaelli/audiotap/blob/main/go/bridge.c), [tmc/apple example](https://github.com/tmc/apple/blob/main/cmd/systap/main.go))

ScreenCaptureKit remains an Apple-supported alternative; its current combined sample requires macOS 15 and screen-recording consent. **Microphone and system-audio consent are separate prerequisites**. The built CLI embeds [verified purpose strings](evidence/embedded-plist.log) and requests microphone authorization. Successful interactive recording demonstrates access in that execution context; signed distribution and unattended LaunchAgent permission identity remain unverified. ([Apple ScreenCaptureKit](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos), [Apple authorization](https://developer.apple.com/documentation/bundleresources/requesting-authorization-for-media-capture-on-macos), [tap permissions](https://developer.apple.com/documentation/coreaudio/capturing-system-audio-with-core-audio-taps))

## Go rotates calendar files; Xiph finalizes audio

The user approved **libopus 1.6.1 and libopusenc 0.3**. The [native build script](../../../../scripts/build-native.sh) verifies published archive checksums and builds static libraries. Xiph classifies libopus 1.6.1 as stable and **libopusenc 0.3 as a development release**. libopusenc supplies Ogg packing and resampling and depends only on libopus; retained license notices are required. The [linkage log](evidence/linkage.log) shows only Apple libraries/frameworks for the current arm64 artifact, with no external codec dylib. Recording source invokes no helper executable. This is one distributable executable using macOS libraries, not a fully static operating-system-independent binary. ([Xiph downloads](https://opus-codec.org/downloads/), [dependencies](https://github.com/xiph/libopusenc), [libopus license](https://github.com/xiph/opus/blob/v1.6.1/COPYING), [libopusenc license](https://github.com/xiph/libopusenc/blob/master/COPYING))

The implemented [encoder](../../../../internal/opus/encoder.go) uses libopusenc's intended pull API, keeping file allocation and writes in Go. Native drain handles codec lookahead and final granule trimming. Go splits PCM by acquisition hour, drains the previous encoder, and starts an independent encoder/file. The passing rotation test feeds a 20 ms block across midnight and verifies two finalized 10 ms files. Clock mapping is compared once per second and reanchored for shifts exceeding one second, retaining queued frames' host-time offsets rather than substituting arrival times. Forward/backward clock tests pass; disabling reanchoring produces the expected failure. Long-running hourly continuity still needs verification. ([Encoding API](https://www.opus-codec.org/docs/libopusenc_api-0.3/group__encoding.html), [clock mapping](../../../../internal/capture/capture.go), [test log](evidence/check.log), [clock negative evidence](evidence/clock-disabled.log))

Pure-Go encoders also exist. Pion has an encoder; thesyncim/gopus supports SILK/CELT/hybrid encoding and reusable buffers, but its inspected Ogg writer lacks the complete delay-drain/final-trim integration. tphakala/go-opus implements integrated stream finalization but deliberately encodes CELT only and exposes no page-duration flush control in the inspected writer. hraban/opus is an established libopus wrapper, but its ordinary configuration neither writes Ogg files nor produces a self-contained executable. These remain alternatives for evaluation rather than substitutes with verified equivalent recorder behavior. ([Pion encoder release](https://github.com/pion/opus/releases/tag/v0.1.0), [thesyncim Ogg writer](https://github.com/thesyncim/gopus/blob/v0.1.1/container/ogg/writer.go), [tphakala encoder](https://github.com/tphakala/go-opus/blob/main/oggopus/encoder.go), [tphakala writer](https://github.com/tphakala/go-opus/blob/main/oggopus/writer.go), [hraban/opus](https://github.com/hraban/opus))

## Streaming preserves complete pages but leaves loss windows

Ogg Opus decoders must handle a stream lacking its end-of-stream flag. Ogg pages have sequence numbers and checksums; an incomplete page or continued packet at the tail can still be unusable. A process crash loses unwritten application state, while machine or power failure adds filesystem and device-cache risks. Go's File.Sync explicitly commits current contents to stable storage; the inspected Go 1.26.2 Darwin implementation uses F_FULLFSYNC with an ENOTSUP fallback. None of these contracts proves successful decoding or power-loss recovery for this recorder. ([RFC 7845](https://www.rfc-editor.org/rfc/rfc7845.html#section-3), [Ogg page format](https://www.rfc-editor.org/rfc/rfc3533.html#section-6), [Go File.Sync](https://pkg.go.dev/os#File.Sync), [Go Darwin synchronization](https://github.com/golang/go/blob/go1.26.2/src/internal/poll/fd_fsync_darwin.go))

The encoder sets decision delay to zero and positive mux delay to 4,800 granule units, targeting 100 ms pages; recording attempts file/log synchronization every five seconds by default, outside the callback. **Zero mux delay disables automatic time-based flushing**, rather than requesting immediate writes. Current settings reduce buffering but do not bound every loss window: capture queues, native encoder state, stalled writes, and sync failures remain relevant. APFS directory-entry durability and power-loss recovery remain unverified. ([Encoder settings](../../../../internal/opus/encoder.go), [recording loop](../../../../internal/recording/run.go), [Ogg packer](https://github.com/xiph/libopusenc/blob/master/src/ogg_packer.c), [Darwin fsync](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/man/man2/fsync.2))

In the completed SIGKILL experiment, interrupted `12-001.opus` decoded with **EOS absent**, retaining 52.294 seconds and 2,510,400 decoded samples. Restart created `12-002.opus`, preserving the earlier files, and then closed normally. This verifies one real interrupted-file prefix and naming recovery, not automatic relaunch or a universal loss bound. Randomized kill timing, torn writes, disk exhaustion, sync errors, and power-loss recovery still need separate evidence. ([Crash decode](evidence/crash-decode.log), [restart journal](evidence/live-log.nljson))

## Recovery needs frame health and a native supervisor

The implemented recorder watches **frame delivery**, timestamps, queue overflow, and device/format notifications. Silence does not trigger resets. Five seconds without frames ends a capture session; transient capture/storage failures retry with backoff from 250 ms to five seconds. A 90-second operation watchdog exits with status 2 to permit supervision after a blocked native call or I/O operation. Its subprocess test passes, but forced native stalls and physical-device recovery are not yet verified. Storage failures retain/replay the pending block while the finite native queue can overflow; logs expose that loss. ([Recording lifecycle](../../../../internal/recording/run.go), [watchdog test](../../../../internal/recording/recording_test.go), [check log](evidence/check.log))

`ambient-recorder service print --output PATH` generates a LaunchAgent plist with absolute paths, KeepAlive enabled, five-second throttling, and a supervisor stderr file. The generated plist passes native [plutil lint](evidence/agent-lint.log); **no agent is installed or running**. Its permission context still needs verification. launchd throttles repeated exits and user agents end at logout; SIGKILL is uncatchable, and sleep/power conditions can stop capture. “May not stop for any reason” therefore means recover-and-retry while prerequisites hold, with diagnosed gaps. A finite buffer cannot retain unlimited storage outages. ([Service implementation](../../../../cmd/ambient-recorder/service.go), [Apple launchd](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/CreatingLaunchdJobs.html), [Go signals](https://pkg.go.dev/os/signal), [Apple sleep assertion](https://developer.apple.com/documentation/iokit/kiopmassertiontypepreventuseridlesystemsleep))

Defaults are mono voice encoding at 32 kbps, complexity 2, DTX disabled, accepting the aggregate's native rate with libopusenc resampling. **Mono is the approved direction** under the user's CPU/Deepgram priorities. Deepgram supports Ogg/Opus, offers optional independent-channel transcription, and says containerized streaming audio should omit the raw-audio `encoding` parameter. Suitability does not establish transcription quality; no Deepgram request has run. ([CLI defaults](../../../../cmd/ambient-recorder/root.go), [Deepgram formats](https://developers.deepgram.com/docs/supported-audio-formats), [encoding](https://developers.deepgram.com/docs/encoding), [multichannel](https://developers.deepgram.com/docs/multichannel))

The [measured run](evidence/live-time5.log) used 1.62 user plus 0.62 system CPU seconds over 157.75 wall seconds: **1.42% of one core**, calculated from recorder process times, excluding other system processes. Peak resident memory was 26,525,696 bytes, approximately **25.3 MiB**. This was a short, mostly quiet run with a 16 kHz Bluetooth aggregate and three-second playback tone. It predates the once-per-second clock comparison, whose additional CPU cost is unmeasured; it is not a worst-case or day-long benchmark. At average payload rates of 24–32 kbps, arithmetic gives 259–346 MB/day before container/log overhead; VBR sizes vary. ([Opus bitrate controls](https://www.opus-codec.org/docs/opus_api-1.6/group__opus__encoderctls.html))

## The CLI builds and filesystem behavior has evidence

The [storage package](../../../../internal/storage/storage.go) reserves `YYYY/MM/DD/HH-000.opus` and increasing suffixes exclusively, retains prior recordings, confines access to the root, uses private creation modes, and locks against competing recorders. The recording loop rotates by local acquisition hour and reopens daily `log.nljson`. The passing suite covers restart allocation, boundaries, concurrency, append, root confinement, and locking. Removing exclusive creation produced duplicate paths and test failure, confirming that the concurrency test catches the regression. ([Green storage log](evidence/storage-green.log), [disabled-change evidence](evidence/storage-disabled.log), [full check](evidence/check.log))

The repository has `main`, `.gitignore`, and `LICENSE`; [CLI source](../../../../cmd/ambient-recorder/root.go) integrates the approved **Cobra v1.10.2 and cobra-help-tree/v2 v2.1.0**, including tree help, catalog, hidden generated commands, and agent mode. `ambient-recorder recording start --output PATH` records until interrupted, with bitrate, complexity, and sync-interval controls. The [manifest](../../../../go.mod) retains approved dependencies; no further package is introduced by this report. ([Approved graph](research/cli.md), [help-tree integration](https://github.com/alexgorbatchev/cobra-help-tree/blob/v2.1.0/README.md))

The approved [Go 1.27.1 toolchain](evidence/go-version.log) builds the recorder. The [just check log](evidence/check.log) shows native build, vet, module hygiene, formatting, race tests across all five Go packages, and executable build. Negative verification disables native drain, rotation splitting, or watchdog exit and obtains the expected failures; a blocked-stderr watchdog regression also failed before its correction. This establishes the checked arm64 development artifact, not signed distribution or Intel compatibility. ([Drain failure](evidence/opus-disabled.log), [rotation failure](evidence/rotation-disabled.log), [watchdog failure](evidence/watchdog-disabled.log), [blocked-stderr failure](evidence/watchdog-stderr-red.log))

The [journal](../../../../internal/recording/journal.go) records device/format, rotation, frames, drops, retries, and write/sync failures outside the callback, with stderr fallback. Tests verify daily JSON append and recovery of a partial final record into a diagnostic event. After clock calibration integration, a final foreground recording decoded **84.480 seconds with EOS**, with zero drops reported and 1,351,680 input frames at 16 kHz. All foreground recorder processes are stopped. ([Final decode](evidence/final-live-decode.log), [live journal](evidence/live-log.nljson), [verification boundaries](verification.md))

## Conclusion

The remaining reliability milestone is sustained operation through device changes, storage faults, process termination, and a verified LaunchAgent permission context. The short recording establishes a working capture/encode/archive path and a useful CPU baseline; it does not establish unattended durability. Meeting-note features should build on diagnostics that distinguish captured silence from missing audio.
